# ADR 0008 — Dashboard frontend stack: Jinja2 + htmx (v1), Svelte 5 (v2 path)

Status: **Accepted** (decision D1 — 1-day ADR, not a fork; v1 ratified with the Phase 1 wave 1 API)
Date: 2026-08-01
Owner: Chief Architect · Reviewers: CTO, SWE, Cloud Architecture
Related: ADR 0002 (backend), ADR 0009 (API contract), `docs/dashboard/initiative.md`

## Context

The dashboard must render ~9 views (Overview, System Health, Agents, Runs &
History, Memory, Reports, Validation gate, Registry/Org graph, Decision inbox),
with ≤5s live refresh over WebSocket, Markdown/Mermaid report rendering, and
write-action confirm dialogs. Two viable stacks:

- **Option A — Jinja2 + htmx (v1):** reuses the existing `Jinja2>=3.1.6`
  dependency; server-rendered fragments; htmx swaps; zero Node toolchain;
  fastest to ship; limited client-side interactivity.
- **Option B — Svelte 5 + Vite:** full interactive SPA; richer UX (approval
  cards, graph panes); adds a Node toolchain + build step to a Python repo;
  slower first shippable slice.

## Decision

**Adopt Option A (Jinja2 + htmx) for v1 (Phases 1–2), with Option B (Svelte 5 +
Vite) documented as the v2 path (Phase 4+).** The API contract (ADR 0009) is
frontend-agnostic, so this choice does not fork the platform. A Svelte shell
could later mount over the same endpoints.

Rationale:
- The project has **no Node toolchain today**; introducing one in Phase 1
  violates the "≤30% of effort on UI" constraint (R7) and slows the read-only
  demo (Phase 1 is 80% of exec value for 30% of effort).
- htmx + Jinja2 covers every Phase 1/2 requirement: fragment refresh,
  WebSocket push, confirm-dialog interactions.
- CTO recommendation aligns; SWE preference for Svelte is captured as v2.

## Consequences

- Positive: fastest path to a working boardroom; keeps the test suite
  Python-only; CSP/DOMPurify story is simple (server-rendered).
- Negative: v2 Svelte port is a rewrite of the view layer only — API and
  services are untouched; must budget it in Phase 4.

## Alternatives rejected

- Single-page JS framework in v1 (too heavy, R7).
- Static HTML generated by prompts (the 16-line stub — rejected, finding #3).
